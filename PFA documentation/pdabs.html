Architecture des Microservices

L'architecture PBADS suit une approche microservices modulaire avec 12 services principaux, chacun ayant une responsabilité spécifique.

Services d'Infrastructure

Eureka Server
Service de découverte et registre des services. Tous les services s'y enregistrent pour être découverts.
Spring Cloud Netflix Eureka
Config Server
Centralise la configuration de tous les services à partir d'un référentiel Git.
Spring Cloud Config Git
API Gateway
Point d'entrée unique pour toutes les requêtes, gère le routage, l'authentification et la limitation de débit.
Spring Cloud Gateway JWT

Organisation des Répertoires

La structure est organisée en plusieurs catégories principales :

  • configuration/ - Contient le serveur de configuration
  • core-services/ - Les services métier principaux (auth, data, model, etc.)
  • gateway/ - Le gateway API
  • service-discovery/ - Le serveur Eureka
  • infrastructure/ - Les services d'infrastructure (Kafka, PostgreSQL, Redis)
  • observability/ - Service de monitoring
  • mlops/ - Services liés au Machine Learning
  • frontend/ - Application React
  • shared/ - Bibliothèques partagées

Microservices du Projet

Le projet comprend 12 microservices principaux, chacun avec une responsabilité spécifique :

1. Eureka Server
Service de découverte - Registre central de tous les services
Port: 8761
2. Config Server
Configuration centralisée - Gère les fichiers de configuration
Port: 8888
3. API Gateway
Point d'entrée unique - Routage, authentification, rate limiting
Port: 8080
4. Auth Service
Authentification et autorisation - JWT, OAuth2, gestion des utilisateurs
Port: 8081
5. Data Service
Gestion des données - CRUD, export, validation des données d'habitudes
Port: 8082
6. Model Service
Service de ML - Entraînement, évaluation, déploiement de modèles
Hybride Java/Python
7. Inference Service
Inférence en temps réel - Détection d'anomalies, chargement de modèles
Port: 8084
8. Alert Service
Gestion des alertes - Notifications, WebSocket, recommandations
Port: 8085
9. Monitoring Service
Observabilité - Métriques, dashboards, alertes système
Prometheus/Grafana
10. Model Registry
Registre de modèles - Versioning, suivi d'expériences ML (MLflow)
MLflow
11. Frontend
Interface utilisateur - React, visualisation des données, gestion des alertes
React Nginx
12. Shared Libraries
Bibliothèques partagées - DTOs, exceptions, utilitaires communs
Java

  • React pour le frontend
  • Python/ML libraries pour le machine learning

Interactions entre les Services

Les services communiquent entre eux via différents patterns et protocoles :

1. Découverte et Configuration

Processus de démarrage :

  1. Le Config Server démarre en premier et lit la configuration depuis Git
  2. Le Eureka Server démarre et écoute sur le port 8761
  3. Chaque microservice démarre et :
    • Se connecte au Config Server pour récupérer sa configuration
    • S'enregistre auprès du Eureka Server avec son nom et adresse
  4. L'API Gateway consulte Eureka pour découvrir les services disponibles

2. Flux d'Authentification

Séquence type :

  1. Utilisateur envoie credentials à l'API Gateway
  2. Gateway route vers Auth Service
  3. Auth Service valide les credentials et génère un JWT
  4. JWT est retourné à l'utilisateur via Gateway
  5. Les requêtes suivantes incluent le JWT dans le header
  6. Gateway valide le JWT avant de router vers les autres services

3. Flux de Données et Détection d'Anomalies

Pour la détection d'anomalies :

  1. Les données d'habitudes sont envoyées au Data Service via Gateway
  2. Data Service persiste les données et publie un événement Kafka
  3. Inference Service consomme l'événement Kafka
  4. Inference Service charge le modèle depuis Model Service ou cache
  5. Inference Service exécute la détection d'anomalies
  6. Si anomalie détectée, Inference Service publie un événement d'alerte
  7. Alert Service consomme l'événement d'alerte et notifie l'utilisateur

4. Types de Communication

Communication Synchrone
HTTP/REST via Feign clients entre services pour les opérations critiques nécessitant une réponse immédiate
Communication Asynchrone
Kafka pour les événements (nouvelles données, anomalies détectées) permettant le découplage
Communication Temps Réel
WebSocket pour les notifications push et mises à jour en temps réel sur le frontend

5. Stratégie de Base de Données

Chaque service a sa propre base de données/schéma :

  • Auth Service : Base de données utilisateurs, rôles, tokens
  • Data Service : Données d'habitudes, logs d'audit
  • Model Service : Métadonnées de modèles, versions
  • Alert Service : Historique des alertes, préférences de notification
  • Monitoring Service : Métriques, seuils d'alertes

Comment Collecter les Données

Plusieurs approches pour collecter des données sur les habitudes personnelles :

Applications Mobiles

Objets Connectés
Montres intelligentes, trackers d'activité (Fitbit, Apple Watch, Garmin)
Journaux Manuels
Saisie quotidienne via une interface web ou mobile dédiée

Comment les Données Aident à la Détection d'Anomalies

Le système PBADS analyse les données pour :

  • Établir des profils de normalité : Comprendre les patterns habituels de l'utilisateur
  • Détecter des déviations : Identifier quand un comportement sort des limites normales
    • Sommeil significativement réduit ou augmenté
    • Changement brusque dans l'appétit ou l'activité physique
    • Augmentation soudaine du temps d'écran
    • Fluctuations inhabituelles de l'humeur
  • Identifier des corrélations : Découvrir des relations entre différents aspects
    • Impact du sommeil sur l'humeur du lendemain
    • Relation entre activité physique et niveau de stress
    • Effet du temps de travail sur la qualité du sommeil
  • Prédire des tendances : Anticiper d'éventuels problèmes avant qu'ils ne surviennent

Exemples d'Anomalies Détectables

Anomalies de Sommeil
Nuits trop courtes (< 6h) ou trop longues (> 10h), horaires de coucher irréguliers
Anomalies Alimentaires
Sauts de repas, consommation calorique extrême, changements brusques
Anomalies d'Activité
Sédentarité soudaine, surexercice, rupture de routine

Algorithmes de Machine Learning Utilisables

Le système peut utiliser plusieurs approches ML :

Algorithme Application Avantage
Isolation Forest Détection d'anomalies multivariées Efficace pour les données haute dimension
LSTM (RNN) Détection d'anomalies séquentielles Capture les dépendances temporelles
One-Class SVM Apprentissage de la "normalité" Robuste aux outliers
Autoencoders Reconstruction et détection d'anomalies Apprentissage non supervisé profond

Conseils pour un Dataset Efficace :

  • Collecter des données sur au moins 30 jours pour établir des patterns
  • Inclure des variables contextuelles (weekend/vacances/maladie)
  • Normaliser les données pour faciliter l'analyse
  • Ajouter des métadonnées temporelles (saison, jour de la semaine)
  • Valider la qualité des données (valeurs manquantes, outliers)
