\section{Description des Composants}

\subsection{Backend (Spring Boot)}
\begin{itemize}
\item \textbf{controllers/} : Points d'entrée de l'API REST
\item \textbf{models/} : Entités JPA et objets de transfert de données
\item \textbf{repositories/} : Interfaces d'accès aux données
\item \textbf{services/} : Logique métier et traitement des données
\end{itemize}

\subsection{Frontend (Angular)}
\begin{itemize}
\item \textbf{components/} : Composants réutilisables de l'interface
\item \textbf{pages/} : Pages principales de l'application
\item \textbf{services/} : Services d'appel à l'API
\item \textbf{utils/} : Fonctions utilitaires et constantes
\end{itemize}

\section{Architecture MVC}

Le projet suit l'architecture Modèle-Vue-Contrôleur (MVC) :

\begin{itemize}
\item \textbf{Modèle} : Représente les données et la logique métier
  \begin{itemize}
  \item Entités JPA pour la persistance
  \item Services pour le traitement des données
  \item Repositories pour l'accès aux données
  \end{itemize}

\item \textbf{Vue} : Interface utilisateur Angular
  \begin{itemize}
  \item Composants réutilisables
  \item Pages et layouts
  \item Styles et assets
  \end{itemize}

\item \textbf{Contrôleur} : Gestion des requêtes et coordination
  \begin{itemize}
  \item Controllers REST
  \item Routing
  \item Validation des données
  \end{itemize}
\end{itemize}

Cette architecture assure :
\begin{itemize}
\item Une séparation claire des responsabilités
\item Une maintenance facilitée
\item Une évolutivité du code
\item Une réutilisation des composants
\item Une testabilité améliorée
\end{itemize}
